# SwiftPrint Configurator & Pricing Engine for WooCommerce

Production-oriented WooCommerce plugin for print shops using **simple products** (no WC variations) with a React configurator and server-validated quote token pricing.

## Installation

1. Copy plugin folder into `wp-content/plugins/`.
2. Activate plugin.
3. Ensure WooCommerce is active.
4. Open **WooCommerce > SwiftPrint** and save schema JSON for a product.
5. In product edit screen, enable **Enable SwiftPrint Configurator**.

## Data schema (stored in custom tables)

### `wp_swiftprint_base_price_sets`
Contains the schema payload and pricing settings:
- `pricing_mode`: `LOOKUP | LPI | LUPI | UP`
- quantity settings (`DROPDOWN | TEXTBOX`) including min/max/step.
- print modes (`front_mode`, `back_mode`, `sides`, `print_mode_key`).
- standard sizes and custom size ranges.
- turnarounds (`cost_type`, `cost_value`, `production_days`, `cutoff_time`).
- option groups/items and smart triggers.
- discount + weight settings and `schema_version`.

### `wp_swiftprint_pricing_rows`
Normalized price rows:
- `base_price_set_id`
- `size_id`
- `print_mode_key`
- `quantity_break`
- `total_price`

### `wp_swiftprint_quote_logs`
Audit trail of issued quote tokens:
- token hash, payload, total/currency, expiry.

## CSV format examples

Single table export/import columns:

```csv
size_id,print_mode_key,quantity_break,total_price
A5,SIMPLE_S1,25,14.00
A5,SIMPLE_S1,50,20.00
A5,SIMPLE_S1,100,30.00
A4,FC_BOTH,100,62.00
```

Export-all can be generated by appending `base_price_set_id` as the first column.

## Pricing mode behavior

Given breakpoints `(50 => 20.00)` and `(100 => 30.00)`, quantity=75:

- `LOOKUP`: nearest lower total -> `20.00`.
- `LPI`: linear interpolation on totals -> `25.00`.
- `LUPI`: interpolate unit prices then multiply qty.
- `UP`: nearest lower unit price stair-step -> `(20/50)*75 = 30.00`.

## Security notes (quote validation)

- Frontend estimates are client-side only.
- `POST /wp-json/swiftprint/v1/quote` recomputes on server and issues an HMAC quote token with expiry.
- Add-to-cart and cart recalculation re-verify token and reprice server-side.
- Selection payload mismatch, signature mismatch, or expiration causes rejection.

## REST API

- `POST /swiftprint/v1/quote`
- `GET /swiftprint/v1/schema/{product_id}`
- `GET|POST /swiftprint/v1/admin/schema/{product_id}` (admin only)

## Extension hooks / filters

- `swiftprint_quote_payload` (recommended custom filter to alter token payload before signing)
- `swiftprint_business_days_holidays` (recommended filter for holiday arrays)
- `swiftprint_reprice_result` (recommended filter after server reprice)

(You can register these in your custom integration plugin by wrapping core service calls.)
